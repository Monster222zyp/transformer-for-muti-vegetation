# 训练产物与结果解释

## 1. `model/artifacts/` 是什么

`model/artifacts/` 是训练和评估的默认产物目录，保存一次运行的配置快照、数据划分、模型权重、训练历史、预测、指标和图片。它被 Git 忽略，属于可重建但通常计算代价较高的本地结果。

当前工作区的该目录约 479.84 MiB，内容是一轮基于根目录 249 条 `dataset.jsonl` 的 `plant_count` 五折训练。它是一个具体实验快照，不代表所有配置和数据版本的通用结果。

## 2. 建议的运行目录结构

不要让多个实验共同写入默认根目录。建议每次使用独立名称：

```text
model/artifacts/
├── run_YYYYMMDD_description/
│   ├── .hydrotransformer-artifacts
│   ├── resolved_config.json
│   ├── fold_assignments.csv
│   ├── fold_0/
│   ├── fold_1/
│   ├── ...
│   ├── cv_metrics.json
│   ├── cv_predictions.csv
│   ├── cv_plant_coefficients.csv
│   ├── final_model.pt
│   └── final_scaler.json
└── smoke_description/
    └── overfit/
```

用户显式传入三份 JSONL 时使用另一套单模型结构：

```text
model/artifacts/predefined_run_001/
├── resolved_config.json
├── predefined_split_assignments.csv
├── predefined_metrics.json
├── predefined_predictions.csv
├── predefined_plant_coefficients.csv
├── predefined_metrics_by_flow_speed.json
├── predefined_metrics_by_flow_speed.csv
└── predefined/
    ├── best.pt
    ├── last.pt
    ├── scaler.json
    ├── history.csv
    ├── validation_metrics.json
    └── test_metrics.json
```

该目录不生成 `final_model.pt`：test 保持只评估，validation 保持只选模型，程序不会自动把三个集合合并重训。

`.hydrotransformer-artifacts` 是 ownership marker，即证明该目录被允许由训练流程管理的标记。它用于阻止程序误清理项目根、用户目录或普通源码目录，不是训练数据。

## 3. 根级产物

| 文件 | 含义 | 维护用途 |
|---|---|---|
| `resolved_config.json` | 合并 YAML、CLI 和绝对路径后的最终配置，还包含实际物理阻力表 | 复现实验时的第一证据 |
| `fold_assignments.csv` | 每条数据在每折中的 train/validation/test 角色 | 检查数据泄漏和留出语义 |
| `cv_metrics.json` | 所有折的详细指标、聚合指标和划分元信息 | 正式结果汇总入口 |
| `cv_metrics_by_flow_speed.json/csv` | 按四档速度聚合的 held-out 指标 | 检查性能是否受流速影响 |
| `cv_predictions.csv` | 合并各折 held-out test 预测 | 误差分析与绘图 |
| `cv_plant_coefficients.csv` | 合并各折 held-out 逐株潜在系数 | 解释性分析，不能当真实逐株力 |
| `cv_drag_comparison.png` | 全部 held-out 样本的预测/真实/孤立阻力对比 | 快速查看总体偏差 |
| `cv_drag_comparison_by_flow_speed.png` | 四个速度面板的对比图 | 查看分速度误差模式 |
| `final_model.pt` | 普通 CV 后用全部数据重训的最终推理模型 | 部署或外部数据评估 |
| `final_scaler.json` | final 模型使用的流速标准化统计量 | 必须与 final 模型配套 |

`predefined` 模式使用对应的 `predefined_*` 根级文件，并额外在 metrics 与 resolved config 中保存三份数据的绝对路径、样本数和 SHA-256。`predefined_split_assignments.csv` 同时记录角色、所属 JSONL、本地 `source_index` 和拼接后的 `dataset_index`，用于消除三个文件都从第 0 行开始造成的歧义。

`flow_speed` 模式只生成固定 `fold_0`，不会执行普通模式的全量 final 重训，因此没有 `final_model.pt` 和 `final_scaler.json`。判断文件是否应该存在时必须先看 `split_mode`。

## 4. 每折目录

| 文件 | 含义 |
|---|---|
| `best.pt` | 验证 loss 最佳时的轻量 checkpoint；适合评估和推理 |
| `last.pt` | 最近保存的完整训练状态；包含 optimizer、scheduler 和 history，用于断点续训 |
| `scaler.json` | 仅由该折训练集拟合的流速均值和标准差 |
| `history.csv/json` | 每个 epoch 的训练相对 MSE、验证相对 MSE和学习率 |
| `loss_curve.png` | 训练与验证 loss 曲线 |
| `validation_metrics.json` | 该折 validation 指标 |
| `test_metrics.json` | 该折 test 指标 |
| `*_metrics_by_flow_speed.*` | 普通模式下按流速拆分的指标 |
| `*_predictions.csv` | validation 或 test 的条件级预测 |
| `*_plant_coefficients.csv` | validation 或 test 的逐株潜在系数 |
| `*_drag_comparison*.png` | 对应集合的预测对比图 |

`best.pt` 和 `last.pt` 不能互换：前者是最佳权重和评估上下文，后者才有继续训练所需的完整状态。

## 5. 评估产物

`python -m model.evaluate` 默认写出：

| 文件 | 含义 |
|---|---|
| `evaluation_metrics.json` | 当前评估集合的回归指标 |
| `evaluation_predictions.csv` | 每个条件的真实、有效和预测总阻力 |
| `evaluation_plant_coefficients.csv` | 每个条件中每株水草的潜在系数 |
| `evaluation_context.json` | 评估范围、source indices 和语义标签 |

`evaluation_context.json` 中常见范围：

| 范围 | 含义 | 能否当独立泛化结果 |
|---|---|---|
| `held_out` | 普通 CV 某折从未参与该模型训练和 early stopping 的 test | 可以，在说明划分粒度后 |
| `validation_test_overlap` | `flow_speed` 模式的 0.4 m/s 同时作为 validation/test | 不可以称为独立 test |
| `in_sample` | final 模型在自己全量训练数据上评估 | 不可以，只表示拟合情况 |
| `external` | 用户显式提供其他严格 JSONL | 取决于外部数据是否真正独立 |

`predefined/best.pt` 自动复评训练时保存的 test JSONL 时也使用 `held_out`。程序会先核对 test 文件的 SHA-256；若同一路径下内容已经改变，会拒绝沿用原 held-out 语义。通过 `--external-data` 主动评估新文件时则标记为 `external`。

## 6. 指标词典

项目将总阻力记作 D，将条件级相互作用系数记作 C：

```text
isolated_drag = Σ 每株 single_drag
target_C = target_drag / isolated_drag
predicted_C = predicted_drag / isolated_drag
```

在纯比值意义上，`C < 1` 表示该条件的总阻力低于孤立单株阻力的线性叠加，`C > 1` 表示高于该基线。但 C 只描述条件级相对比例，不能单独证明遮挡、协同或某一对植株之间的因果机制。当前 `target_C` 使用已经按负标签策略处理的 `target_drag`；解释 C 时必须同时声明 `clamp_to_zero` 是否启用，并保留对 `raw_target_drag` 的审计。

| 指标 | 直观意义 | 注意事项 |
|---|---|---|
| `MAE_D` | 预测总阻力与真实总阻力的平均绝对差 | 与 D 同单位，暂按 N |
| `RMSE_D` | 总阻力误差的均方根 | 对少数大误差更敏感，单位同 D |
| `R2` | 相比使用真实均值，模型解释了多少变化 | 可为负；样本小或分组窄时波动大 |
| `MAE_C` | 条件级相互作用系数的平均绝对误差 | 无量纲 |
| `RMSE_C` | C 误差的均方根 | 无量纲，对大误差更敏感 |
| `MAPE_D` | 总阻力绝对百分比误差 | 只统计 `target_drag > 1e-6`，必须同时看 coverage |
| `MAPE_coverage` | 有多少样本进入 MAPE | 小于 1 表示部分零/近零目标被排除 |
| `sMAPE_D` | 对称百分比误差 | 能较安全处理零标签，但仍应结合绝对误差 |

训练 loss 是稳定化相对 MSE，不等于上面任一报告指标。它使用只由训练集正标签拟合的分母下限，防止零或很小目标导致数值爆炸。

## 7. 如何阅读预测表

建议按以下顺序：

1. 查看 `resolved_config.json`，确认数据路径、split mode、物理表和负标签策略。
2. 查看 `fold_assignments.csv`，确认同一分组没有跨 train/test 泄漏。
3. 查看 `cv_metrics.json` 的 `validation_test_overlap` 和 `final_retraining_performed`。
4. 先读 held-out 的 `MAE_D/RMSE_D/R2`，再读 C 指标和百分比指标。
5. 比较 `predicted_drag` 与 `isolated_drag`，判断模型是否学到了相对孤立叠加的修正。
6. 按 `flow_speed`、`plant_count`、`model_id` 和角度分组检查误差集中位置。
7. 最后查看逐株系数图，作为模型内部空间模式的线索，不作为独立物理测量。

## 9. checkpoint 与可复现性

Checkpoint 会保存模型结构、scaler、数据路径、负标签策略、物理配置、loss 信息和评估范围。历史 checkpoint 的绝对数据路径可能只在原机器有效，但其中保存的 source indices 和配置仍能帮助追溯。

复现实验至少需要一起保存：

- 输入 JSONL 或不可变数据版本及哈希；
- `resolved_config.json`；
- `physical.yaml` 的实际解析值；
- `fold_assignments.csv`；
- 每折 `best.pt`；
- `cv_metrics.json` 和预测 CSV；
- 运行时 Python、PyTorch、CUDA 与依赖版本；
- 对应 Git commit 和工作区是否有未提交修改。

只保存 `final_model.pt` 无法完整解释它如何得到，也无法复核 held-out 泛化结果。

## 10. 清理与归档

训练入口会保护明显危险的目录，但重要实验仍应主动归档。建议：

- 每次运行使用独立子目录；
- 将结果目录与数据版本、配置名称建立一一对应；
- 只删除已经确认可重建且已有归档的产物；
- 不手工混合不同运行的 fold；
- 不把旧 `fold_1`～`fold_4` 留在新的单折 `flow_speed` 目录中；
- 发布时保留指标和轻量 checkpoint，大体积 `last.pt` 可按恢复需求另行归档。
