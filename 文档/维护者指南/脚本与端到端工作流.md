# 脚本与端到端工作流

## 1. 使用约定

以下命令默认从仓库根目录执行，示例使用 Windows PowerShell 和 Python 3.11：

```powershell
py -3.11 path/to/script.py
py -3.11 -m model.train
```

`python -m model.train` 中的 `-m` 表示按 Python 模块运行。模型入口必须这样运行，才能稳定解析 `model` 包中的导入。

参数写成 `--name value`。布尔开关通常用 `--flag` 启用，具体以 `--help` 为准：

```powershell
py -3.11 Experiment/filter_sensor_data.py --help
py -3.11 -m model.train --help
```

## 2. 环境准备

项目没有统一 lock file（精确锁定所有依赖版本的文件）。模型侧版本范围位于 `model/requirements.txt`，实验滤波还需要未列入其中的 SciPy：

```powershell
py -3.11 -m pip install -r model/requirements.txt
py -3.11 -m pip install scipy
```

主要第三方组件：

| 组件 | 用途 |
|---|---|
| NumPy / pandas | 数组、CSV 和表格处理 |
| SciPy | 低通和带通滤波 |
| PyYAML | 读取训练与物理配置 |
| scikit-learn | 分组交叉验证等辅助功能 |
| PyTorch | HydroTransformer 训练和推理 |
| Matplotlib | 构型、曲线、预测和解释图 |
| pytest | 自动化测试 |

## 3. 正式端到端流程

### 3.1 从原始测量重建完整数据

```powershell
py -3.11 Experiment/filter_sensor_data.py
py -3.11 Experiment/summarize_sensor_data.py
```

第一条命令从 `data/` 读取无表头六轴 sensor CSV，生成 `filtered_data/`。当前有 4 个已知短文件会失败，脚本可能返回非零状态，但其余成功文件仍会保留。

第二条命令读取 `filtered_data/` 和 `Experiment/input.csv`，在 `Experiment/output/` 同时生成审计 CSV 与模型 JSONL。默认严格模式要求当前已知的 332 条基线完全匹配。

### 3.2 训练前连通性检查

先运行快速测试：

```powershell
py -3.11 -m pytest model/tests/test_training_utils.py -q
```

再用少量样本做 overfit。Overfit 是故意让模型记住一个小批次，用于发现数据、网络、loss 或反向传播无法工作的问题；它不是泛化评估。

```powershell
py -3.11 -m model.train --mode overfit `
  --data Experiment/output/dataset.jsonl `
  --artifact-dir model/artifacts/smoke `
  --max-epochs 300
```

### 3.3 正式训练

```powershell
py -3.11 -m model.train --mode cv `
  --data Experiment/output/dataset.jsonl `
  --artifact-dir model/artifacts/run_001
```

`cv` 是 cross-validation（交叉验证）：轮换留出不同数据组，用于估计模型对未见条件的表现。当前 `base.yaml` 实际默认 `split_mode: plant_count`、5 折、batch 32、最多 500 epoch。

建议总是使用新的产物目录。Fresh run 在确认配置、数据和划分有效后会清理目标目录中的旧训练产物。

### 3.4 使用自己划分的三个 JSONL

三份文件继续使用原 `dataset.jsonl` 的严格 schema v1。先在 `model/configs/base.yaml` 中设置：

```yaml
mode: predefined
predefined_split:
  train_dataset_path: path/to/train.jsonl
  validation_dataset_path: path/to/validation.jsonl
  test_dataset_path: path/to/test.jsonl
```

相对路径按项目根目录解释，然后运行：

```powershell
py -3.11 -m model.train --artifact-dir model/artifacts/predefined_run_001
```

也可以通过命令行临时覆盖这些 YAML 值：

```powershell
py -3.11 -m model.train --mode predefined `
  --train-data path/to/train.jsonl `
  --validation-data path/to/validation.jsonl `
  --test-data path/to/test.jsonl `
  --artifact-dir model/artifacts/predefined_run_001
```

train 只用于更新模型和拟合训练统计量，validation 只用于 early stopping，test 只用于最佳 checkpoint 的最终评估。三个集合之间不得出现相同 `sample_id`。该模式不会执行 final retraining，推荐模型为 `predefined/best.pt`。

### 3.5 独立评估

评估普通交叉验证某一折的留出测试集：

```powershell
py -3.11 -m model.evaluate `
  --checkpoint model/artifacts/run_001/fold_0/best.pt `
  --output-dir model/artifacts/run_001/evaluation_fold_0
```

评估 final 模型在它原来的全量训练数据上的拟合情况：

```powershell
py -3.11 -m model.evaluate `
  --checkpoint model/artifacts/run_001/final_model.pt `
  --output-dir model/artifacts/run_001/evaluation_final
```

该结果会标记为 `in_sample`，不能当作新数据泛化表现。

评估外部 JSONL：

```powershell
py -3.11 -m model.evaluate `
  --checkpoint model/artifacts/run_001/final_model.pt `
  --data path/to/external_dataset.jsonl `
  --external-data `
  --output-dir model/artifacts/run_001/evaluation_external
```

外部输入仍必须满足严格 JSONL 契约；普通 CSV 不能直接传给当前评估入口。

`predefined/best.pt` 不传 `--data` 时会自动复评保存的 test JSONL，并核对文件 SHA-256。传入任意其他 JSONL 时必须增加 `--external-data`，此时评估全部行并标记为 `external`。

## 4. Experiment 目录脚本

### 4.1 `build_groups.py`：批量重建计划构型

用途：按固定植株数配方，一次生成 17 个六边形构型。

```powershell
py -3.11 Experiment/build_groups.py `
  --output Experiment/input.csv `
  --overwrite `
  --seed 20260809
```

主要参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--output` | `Experiment/input.csv` | 构型输出文件 |
| `--overwrite` | 关闭 | 允许删除现有输出并重建 |
| `--seed` | 无固定值 | 随机构型生成种子 |

该脚本通过多次调用 `generator.py` 生成 17 行。日常训练不需要运行它。带 `--overwrite` 会先删除现有构型文件，而构型行号与全部 `model_N` 数据绑定，因此只应在明确重建实验设计时使用。

### 4.2 `generator.py`：生成或追加单个构型

用途：在排除六种旋转等价重复的前提下，生成指定植株数的新构型。

```powershell
py -3.11 Experiment/generator.py `
  --point-count 8 `
  --append-count 1 `
  --input Experiment/input.csv `
  --output Experiment/input.csv `
  --seed 20260809
```

主要参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--point-count` | 必填 | 新构型的植株数，允许 2～37 |
| `--append-count` | 1 | 一次追加的构型数 |
| `--input` | `Experiment/input.csv` | 用于重复检查的已有构型 |
| `--output` | `Experiment/input.csv` | 写出文件；与输入相同时原地追加 |
| `--allow-missing-input` | 关闭 | 首次生成时允许输入文件不存在 |
| `--seed` | 无固定值 | 随机种子 |

生成器强制点位 0 和 36 为 1。它会覆盖写出“旧行 + 新行”，不是数据库式事务；修改前先备份并核对行号映射。

### 4.3 `visualize_hex_lattice.py`：检查构型和旋转

用途：把 37 位构型绘成六边形总览，并导出六个角度的旋转图。

```powershell
py -3.11 Experiment/visualize_hex_lattice.py --show-ids
```

主要参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--input` | `Experiment/input.csv` | 构型 CSV |
| `--output` | `Experiment/hex_lattice.svg` | 总览 SVG |
| `--output-root` | `Experiment/rotated_plots` | 各构型旋转图目录 |
| `--row` | 全部 | 只在总览图中选择某一行 |
| `--show-ids` | 关闭 | 在图中显示点位编号 |
| `--columns` | 4 | 总览图列数 |

注意：`--row` 只限制总览 SVG；旋转图导出仍会读取完整构型文件并生成所有组。

### 4.4 `motion_profile.py`：生成拖曳控制轨迹

用途：实验前生成 0.1～0.4 m/s 四档、6 秒的加速—匀速—减速轨迹。

```powershell
py -3.11 Experiment/motion_profile.py
```

脚本没有 CLI 参数，主要默认值定义在文件开头：加速 1 秒、总时长 6 秒、速度 0.1～0.4 m/s、步长 0.1 m/s、采样间隔 0.01 秒。输出到根目录 `output/V_*.csv`。

### 4.5 `adapter.py`：编号运动轨迹

用途：检查轨迹并复制为设备使用的数字文件名，同时写出 `mapping.json`。

```powershell
py -3.11 Experiment/adapter.py
```

脚本没有 CLI 参数，固定读取根目录 `output/`，写入 `output/renamed/`，路径上限为 2000 mm。

当前检查的是 `x` 列的有符号总和，不是绝对累计路程。失败分支会清空 `renamed/`；成功时不会主动删除比本次数量更大的旧编号文件，因此数据减少后应人工检查是否残留。

### 4.6 `filter_sensor_data.py`：正式 sensor 过滤

用途：批量发现原始六轴 sensor CSV，截取分析区间、修复短缺失段并执行低通或带通滤波。

```powershell
py -3.11 Experiment/filter_sensor_data.py
```

常用参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--input-path` | `data` | 文件或原始数据根目录 |
| `--output-path` | `filtered_data` | 输出根目录 |
| `--mode` | `lowpass` | `lowpass` 或 `bandpass` |
| `--fs` | 500 | 采样率 Hz |
| `--cutoff` | 2 | 低通截止频率 Hz |
| `--low` / `--high` | 0.05 / 1.0 | 带通范围 Hz |
| `--order` | 5 | Butterworth 低通阶数 |
| `--numtaps` | 401 | Hamming FIR 带通长度，必须为奇数 |
| `--columns` | `all` | 要过滤的列，可用轴名或 0～5 下标 |
| `--trim-head` | 1200 | 起始索引，包含 |
| `--trim-tail` | 2800 | 结束索引，不包含；0 表示到末尾 |
| `--max-nan-gap` | 5 | 允许线性插值的最大连续缺失行数 |

默认会绘图并覆盖同名滤波结果。单文件失败不会终止整个批次：全部成功返回 0，找不到合法文件返回 1，部分失败返回 2。当前四个短记录会使整批结果出现“部分失败”，但 332 个有效条件仍能继续汇总。

### 4.7 `summarize_sensor_data.py`：正式条件级汇总

用途：对每个过滤后文件做逐列截尾平均、统一力坐标、关联旋转构型，同时生成 CSV 和 JSONL。

```powershell
py -3.11 Experiment/summarize_sensor_data.py
```

主要参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--input-path` | `filtered_data` | 过滤后 sensor 根目录 |
| `--output-path` | `Experiment/output/summarized_data.csv` | 审计 CSV |
| `--dataset-path` | `Experiment/output/dataset.jsonl` | 模型 JSONL |
| `--input-csv` | `Experiment/input.csv` | 构型定义 |
| `--trim-fraction` | 0.10 | 每列两端各删除的比例 |
| `--overwrite` | 默认启用 | 允许覆盖输出 |
| `--strict` | 默认启用 | 验证当前 14 构型、332 条基线 |

对新实验批次可临时使用 `--no-strict` 查看问题，但正式纳入后应更新严格基线、缺失条件清单和测试。该脚本已经旋转平均后的 FX/FY；不要先用独立旋转脚本处理输入后再汇总。

### 4.8 `rotate_force.py`：历史独立旋转工具

用途：把整条 sensor 时间序列的平面力分量旋转到 0° 坐标系，固定从 `data/` 写到 `data/datanew/`。

```powershell
py -3.11 Experiment/rotate_force.py
```

它不属于正式主链。正式汇总只在求平均后复用其中的坐标变换功能。除非维护历史流程，不要把 `data/datanew/` 当作 `summarize_sensor_data.py` 的标准输入。

### 4.9 `gather_data.py`：历史运动数据诊断

用途：读取 `gather_*.csv` 或 `gatehr_*.csv`，导出位移/速度数据和诊断图。

```powershell
py -3.11 Experiment/gather_data.py `
  --input-path data/model_1
```

默认采样率 100 Hz、offset 模式为 `initial`、固定 offset 参数为 5，默认绘图。若不传输出路径，会在输入目录下创建 `gather_figure/`。它不参与正式 sensor 汇总或模型训练。

## 5. 模型训练与评估入口

### 5.1 `python -m model.train`

用途：统一执行配置解析、数据验证、划分、训练、预测、指标汇总和图表生成。

```powershell
py -3.11 -m model.train --mode cv --config model/configs/base.yaml
```

主要 CLI：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--mode` | 读取 YAML `mode`，当前为 `cv` | `overfit` 诊断、`cv` 自动划分，或 `predefined` 显式三分集 |
| `--config` | `model/configs/base.yaml` | 训练配置 |
| `--data` | 不覆盖 YAML | 输入 JSONL |
| `--train-data` | 读取 YAML `predefined_split.train_dataset_path` | `predefined` 的训练集 JSONL |
| `--validation-data` | 读取 YAML `predefined_split.validation_dataset_path` | `predefined` 的验证集 JSONL |
| `--test-data` | 读取 YAML `predefined_split.test_dataset_path` | `predefined` 的测试集 JSONL |
| `--physics-config` | 不覆盖 YAML | 单株物理阻力表 |
| `--artifact-dir` | 不覆盖 YAML | 本次输出目录 |
| `--device` | 不覆盖 YAML | `auto`、CPU 或 CUDA 设备 |
| `--batch-size` | 不覆盖 YAML | 每批样本数 |
| `--max-epochs` | 不覆盖 YAML | 最大训练轮数 |
| `--seed` | 不覆盖 YAML | 可复现随机种子 |
| `--resume-checkpoint` | 无 | 仅 overfit 支持的恢复点 |

当前 `base.yaml` 的 `dataset_path` 是本机绝对路径，指向根目录 249 条 `dataset.jsonl`。跨机器运行或希望使用完整 332 条数据时，应显式传 `--data` 或建立独立 YAML。

### 5.2 五种数据划分

| `split_mode` | 留出单位 | 能回答的问题 | 主要风险 |
|---|---|---|---|
| `sample` | 单条条件 | 同分布条件插值 | 同一构型可能出现在不同集合，结果偏乐观 |
| `model` | 完整 `model_id` | 对未见几何构型的泛化 | 独立构型只有 14 个 |
| `plant_count` | 完整植株数分组 | 对未见植株数量的泛化 | 同折样本规模可能不均衡 |
| `flow_speed` | 固定速度 | 用前三档预测 0.4 m/s | 0.4 同时用于 validation 和 test，不是独立 held-out |
| `predefined` | 三个独立 JSONL | 完全复用用户已有的 train/validation/test 协议 | 用户必须自行保证划分代表正确科研问题；程序只额外检查重复 `sample_id` |

当前 `base.yaml` 的运行模式默认是 `cv`，自动划分策略默认是 `plant_count`。前四种划分策略通过 YAML 的 `cross_validation.split_mode` 选择；显式三分集则通过 YAML 的 `mode: predefined` 和 `predefined_split` 三条路径选择。CLI 可临时覆盖 `mode` 和每条路径。

### 5.3 恢复 overfit 训练

```powershell
py -3.11 -m model.train --mode overfit `
  --artifact-dir model/artifacts/smoke `
  --resume-checkpoint model/artifacts/smoke/overfit/last.pt
```

用于恢复的是 `last.pt`；`best.pt` 是轻量评估 checkpoint，不含完整优化器和训练历史。CV 入口当前不提供同样的统一恢复参数。

### 5.4 `python -m model.evaluate`

用途：从 checkpoint 恢复模型、scaler、物理表和评估范围，生成独立指标与预测文件。

主要参数：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `--checkpoint` | 文件顶部默认为空 | `best.pt`、`last.pt` 或 `final_model.pt`；通常仍由 CLI 指定 |
| `--data` | 文件顶部为空，随后回退到 checkpoint 原数据 | 评估 JSONL |
| `--external-data` | 关闭 | 明确允许用非 checkpoint 原数据 |
| `--output-dir` | `model/artifacts/evaluation` | 评估产物目录 |
| `--device` | `auto` | 运行设备 |
| `--batch-size` | 32 | 推理 batch 大小 |
| `--num-workers` | 0 | 数据加载工作进程数 |

修改 `physical.yaml` 后评估旧 checkpoint，程序仍优先使用 checkpoint 内嵌的旧物理表，这是为了保持历史模型语义可复现。

同样的默认值都集中在 `model/evaluate.py` 开头：`DEFAULT_CHECKPOINT_PATH`、`DEFAULT_DATA_PATH`、`DEFAULT_OUTPUT_DIR`、`DEFAULT_EXTERNAL_DATA`、`DEFAULT_DEVICE`、`DEFAULT_BATCH_SIZE` 和 `DEFAULT_NUM_WORKERS`。填写这些变量后可以直接运行 `py -3.11 -m model.evaluate`；CLI 会覆盖代码默认值。

## 7. 常见维护任务

### 新增实验数据

1. 先确认构型行号和 `model_N` 对应关系。
2. 按 sensor 命名规则放入 `data/model_N/`。
3. 保存实验元数据和缺失说明。
4. 运行 filter，再运行 summarize。
5. 核对新 JSONL 的样本数和流速分布。
6. 先 overfit，再用新的 artifact 目录执行 CV。

### 修改构型

不要重排已经有实验数据的前 14 行。若仅新增 `model_18`，应追加新行而不是插入中间。任何六边形编号或旋转规则变化都必须同步核对构型生成、汇总、模型几何、可视化和测试。

### 修改数据处理参数

更改采样率、截取窗口、滤波器、缺失插值、截尾比例或坐标旋转后：

1. 记录新参数和原因；
2. 重建整个 `filtered_data/`；
3. 重建 CSV/JSONL；
4. 不复用旧 checkpoint；
5. 使用新 artifact 目录；
6. 在结果报告中声明数据处理版本。

### 修改训练划分

复制 `base.yaml` 为新的实验配置，修改 `cross_validation.split_mode`，不要只改完再忘记记录。训练会把解析后的绝对配置保存为 `resolved_config.json`，结果解释应以它为准。

### 发布结果前

```powershell
py -3.11 -m pytest model/tests -q
```

随后检查：数据路径、样本数、split mode、validation/test 是否重叠、是否执行 final retraining、每折指标和分流速指标。普通 CV 应优先报告 held-out 聚合结果；final 模型在原数据上的评估只用于拟合复核。

## 8. 会覆盖或删除文件的操作

| 操作 | 风险 |
|---|---|
| `build_groups.py --overwrite` | 删除并重建 `input.csv`，可能破坏构型与实验目录映射 |
| `generator.py` 输入输出同路径 | 重写构型 CSV 为“原有行 + 新增行” |
| `visualize_hex_lattice.py` | 覆盖同名总览 SVG 和旋转图 |
| `motion_profile.py` | 覆盖根目录同名 `output/V_*.csv` 轨迹 |
| `filter_sensor_data.py` 默认运行 | 覆盖同名滤波 CSV 和图 |
| `summarize_sensor_data.py` 默认运行 | 覆盖正式汇总 CSV/JSONL |
| Fresh `model.train` | 清理目标 `artifact_dir` 中旧训练产物 |
| `plot_plant_coefficients.py` | 清空配置的可视化输出目录 |
| 两个速度筛选脚本 | 原地替换 JSONL，无备份 |
| `adapter.py` 失败分支 | 可能清空 `output/renamed/` |

任何上述操作都应使用精确路径和专用输出目录。正式数据与重要结果至少保留一个独立、可验证的副本。
