# 数据字典与文件物理意义

## 1. 阅读原则

本项目同时保存原始时间序列、派生时间序列、条件级汇总表、模型输入、训练产物和可视化副本。它们的字段可能相似，但用途和权威性不同。

维护时先判断文件属于哪一层：

```text
实验计划 → 原始测量 → 滤波测量 → 条件级汇总 → 模型输入 → 训练产物 → 可视化副本
```

只有上游文件能定义下游文件的物理来源。不要把预测表当作实验测量，也不要把为了绘图筛选出的子集覆盖正式完整数据。

## 3. 构型文件 `Experiment/input.csv`

### 3.1 格式

- 文本 CSV；
- 无表头；
- 每行固定 37 列；
- 每个值只能是整数 `0` 或 `1`；
- 第 N 行对应 `model_N`；
- 点位 0 和 36 必须为 `1`。

示意行：

```text
1,0,0,...,0,1
```

实际序列必须有完整 37 项；省略号只用于本文示意。

### 3.2 物理意义

第 i 列表示六边形网格编号 i 的安装状态：

- `1`：该候选点安装了一根水草；
- `0`：该候选点为空。

它不包含水草高度、直径、材料或真实间距。一个构型旋转后，汇总数据中的 `vegetation_layout` 会保存与当前角度一致的旋转后 37 位字符串。

### 3.3 当前文件关系

`Experiment/input.csv` 被 `.gitignore` 忽略，但汇总脚本默认读取它；`Experiment/input copy.csv` 被 Git 追踪，且当前内容相同。仓库没有自动同步两者的机制。建议项目负责人指定一份版本控制基线；在此之前，修改任何一份后都应人工比较并记录差异。

## 4. 原始 sensor CSV

### 4.1 路径和命名

```text
data/model_N/sensor_A_angB.csv
```

| 名称部分 | 含义 |
|---|---|
| `model_N` | 第 N 个构型，对应 `input.csv` 第 N 行 |
| `sensor_A` | 速度档编号，不是四台不同传感器 |
| `angB` | 构型实验角度 B，单位为 degree |

速度档映射：

| 文件编号 | `flow_speed` |
|---:|---:|
| `sensor_1` | 0.1 m/s |
| `sensor_2` | 0.2 m/s |
| `sensor_3` | 0.3 m/s |
| `sensor_4` | 0.4 m/s |

### 4.2 文件格式

- 逗号分隔；
- 无表头；
- 每行恰好 6 个数；
- 默认采样率按 500 Hz 解释；
- 列顺序固定为 `TX, TY, TZ, FX, FY, FZ`。

| 列下标 | 名称 | 当前处理中的意义 | 单位状态 |
|---:|---|---|---|
| 0 | `TX` | 保留并做统计，目前不作为训练标签 | 未确认 |
| 1 | `TY` | 保留并做统计，目前不作为训练标签 | 未确认 |
| 2 | `TZ` | 保留并做统计，目前不作为训练标签 | 未确认 |
| 3 | `FX` | 旋转前的平面主力分量 | 项目暂按 N 使用，需传感器记录确认 |
| 4 | `FY` | 与 FX 一起旋转到统一 0° 坐标 | 未确认 |
| 5 | `FZ` | 保留并做统计，目前不作为训练标签 | 未确认 |

`T` 和 `F` 的命名看起来分别对应力矩与力，但仓库没有传感器型号、标定矩阵和单位说明。维护文档不得仅凭字母把 `TX/TY/TZ` 宣称为某个确定单位。

### 4.3 当前原始文件的物理地位

sensor CSV 是当前正式训练数据链的原始测量来源。默认流程没有额外执行以下步骤：

- 传感器去皮或零点补偿；
- 静水基线扣除；
- 无水草装置阻力扣除；
- 长期漂移补偿；
- 安装方向标定矩阵校正。

如果实验现场事实上做过这些操作，应把步骤、参数和版本补进实验记录；不能仅凭最终数值推测。

## 5. 历史 gather 数据

`data/model_N/gather_*.csv` 或历史拼写 `gatehr_*.csv` 是运动采集类数据，不是六轴 sensor 输入。文件通常使用空白分隔，结构为一列公共信息后跟若干组三列数据，具体组数由文件决定。

`Experiment/gather_data.py` 会从中提取位移和速度并生成诊断 CSV/图。当前正式汇总脚本不会读取 gather 文件，模型训练也不读取它们。因此：

- 不要把 gather 文件改名成 `sensor_*.csv`；
- 不要把 gather 派生量合并进正式 JSONL，除非研究方案明确新增特征；
- gather 各列的完整设备语义尚未形成正式数据字典，当前应视为历史辅助记录。

## 6. 滤波后的 sensor CSV

### 6.1 路径和格式

默认低通输出：

```text
filtered_data/model_N/sensor_A_angB_lowpass_filtered.csv
```

带通模式输出名称包含 `_bandpass_filtered.csv`。文件仍然是无表头、六列、逗号分隔，列顺序不变。

### 6.2 默认处理含义

正式默认参数：

| 项目 | 默认值 | 含义 |
|---|---:|---|
| 采样率 | 500 Hz | 将样本索引换算为时间、设计滤波器 |
| 截取范围 | `[1200, 2800)` | 最多保留 1600 个采样点 |
| 时间范围 | `[2.400, 5.600) s` | 相对 sensor 文件记录起点，不代表已经与运动轨迹同步 |
| 滤波器 | 5 阶 Butterworth 低通 | 保留慢变化趋势 |
| 截止频率 | 2 Hz | 抑制高于主要变化尺度的噪声 |
| 实现方式 | 零相位双向滤波 | 尽量避免单向滤波带来的相位偏移 |
| 处理列 | 6 列全部 | 每列独立处理 |
| 最大内部缺失段 | 5 行 | 以内线性插值；更长则该文件失败 |

典型原始文件有 4100 行，默认处理后为 1600 行。长度不足 2800 时会处理到实际末尾；总行数不大于 1200 时无法取得有效片段。

### 6.3 派生性质

`filtered_data/` 是可重建派生数据，不应比 `data/` 和处理参数拥有更高权威性。更改截取区间、滤波方式或缺失值规则后，必须重建全部滤波数据和所有下游汇总、训练结果。

## 7. 条件级汇总 CSV

### 7.1 正式路径

```text
Experiment/output/summarized_data.csv
```

根目录 `summarized_data.csv` 当前是同一份 332 条审计表的副本。

### 7.2 schema

正式 CSV 有表头，每行表示一个“构型 × 角度 × 可用流速”条件，共 11 列：

| 字段 | 类型 | 物理或管理意义 | 单位 |
|---|---|---|---|
| `sample_id` | 字符串 | 稳定样本 ID，格式为 `model_001_angle_000_flow_0.1` | 无 |
| `model_id` | 整数 | 构型编号 N | 无 |
| `angle` | 整数 | 当前实验角度 | degree |
| `vegetation_layout` | 37 位字符串 | 当前角度下旋转后的占位排布 | 0/1 |
| `TX` | 浮点数 | 过滤序列 TX 列的截尾平均 | 未确认 |
| `TY` | 浮点数 | 过滤序列 TY 列的截尾平均 | 未确认 |
| `TZ` | 浮点数 | 过滤序列 TZ 列的截尾平均 | 未确认 |
| `FX_0` | 浮点数 | 将平均 FX/FY 旋转到统一 0° 坐标后的主力分量；训练标签来源 | 暂按 N |
| `FY_0` | 浮点数 | 旋转到统一 0° 坐标后的横向力分量 | 未确认 |
| `FZ` | 浮点数 | 过滤序列 FZ 列的截尾平均 | 未确认 |
| `flow_speed` | 浮点数 | 相对流速 | m/s |

### 7.3 截尾平均

对六个测量列分别排序，各自删除最低 10% 和最高 10%，再计算中间值的均值。每端删除数为 `floor(该列行数 × 0.10)`。

这是逐列独立截尾，而不是删掉完整时间行。因此六个汇总值不一定来自同一批时间点。若未来研究六轴瞬时相关性，不能直接把这套方法当成保留时间同步的异常值过滤。

### 7.4 力坐标旋转

汇总脚本在求平均后只旋转 FX/FY：

```text
FX_0 = FX × cos(angle) + FY × sin(angle)
FY_0 = -FX × sin(angle) + FY × cos(angle)
```

`TX/TY/TZ/FZ` 不旋转。正式汇总 CSV 已经包含旋转结果，训练前不要再次旋转。

### 7.5 `visualization/summarized_data_0.4.csv` 的区别

该文件仅含 84 条 0.4 m/s 数据，表头为：

```text
model_id,angle,state,vegetation_layout,TX,TY,TZ,FX_0,FY_0,FZ,flow_speed
```

它用 `state` 替代正式表中的 `sample_id`，因此不是正式汇总 schema 的无损替代品。它适合已有可视化流程，不应直接覆盖 `Experiment/output/summarized_data.csv`。

## 8. 模型 JSONL 契约

### 8.1 为什么使用 JSONL

JSONL 是“每一行一个独立 JSON 对象”的文本格式。它适合本项目，因为不同构型包含不同数量的水草，`plants` 可以是变长数组，而每个条件仍能单独读取和定位错误。

文件必须使用 UTF-8 文本，每个非空行都是完整对象。当前 schema 版本固定为 1；模型数据加载器会拒绝缺失字段、额外字段、非法类型和不一致坐标。

### 8.2 顶层字段

| 字段 | 类型 | 约束与意义 |
|---|---|---|
| `schema_version` | 整数 | 必须为 `1` |
| `sample_id` | 非空字符串 | 条件唯一标识，不应重复 |
| `model_id` | 整数 | 构型编号 |
| `angle` | 整数 | 允许的实验角度；当前为六个 60° 间隔值 |
| `flow_speed` | 有限浮点数 | 相对流速，单位 m/s |
| `vegetation_layout` | 字符串 | 恰好 37 个 `0/1`，与当前角度一致 |
| `plants` | 非空数组 | 所有已安装水草的逐株记录 |
| `measurements` | 对象 | 六个条件级测量汇总值 |

### 8.3 `plants` 数组

每个元素固定包含：

| 字段 | 类型 | 含义 |
|---|---|---|
| `plant_index` | 整数 | 当前样本中从 0 连续递增的植株序号 |
| `grid_index` | 整数 | 0～36 的六边形格点编号；数组内严格递增且不重复 |
| `x` | 浮点数 | 无量纲网格 x 坐标，相邻格点距离为 1 |
| `y` | 浮点数 | 无量纲网格 y 坐标，相邻格点距离为 1 |
| `angle` | 整数 | 当前植株角度；现有数据要求等于样本顶层 `angle` |

`plants` 中的 `grid_index` 集合必须与 `vegetation_layout` 中所有值为 1 的位置完全一致。`x/y` 必须与该 `grid_index` 的标准六边形坐标一致，不允许自由填写实验米制坐标。

### 8.4 `measurements` 对象

固定字段为：

```text
TX, TY, TZ, FX_0, FY_0, FZ
```

每个值都必须是有限数。训练的原始目标是 `measurements.FX_0`。当前默认负标签策略为 `clamp_to_zero`：训练使用 `max(FX_0, 0)`，同时在预测表中保留原始值用于审计。

### 8.5 一个结构示例

以下示例只展示形状，数值并非新数据模板：

```json
{
  "schema_version": 1,
  "sample_id": "model_001_angle_000_flow_0.1",
  "model_id": 1,
  "angle": 0,
  "flow_speed": 0.1,
  "vegetation_layout": "1000001000000000000000000100000000001",
  "plants": [
    {"plant_index": 0, "grid_index": 0, "x": 2.598076211353316, "y": 1.5, "angle": 0}
  ],
  "measurements": {
    "TX": -0.0139,
    "TY": -0.0786,
    "TZ": 0.0056,
    "FX_0": 0.2405,
    "FY_0": -0.0337,
    "FZ": 0.1102
  }
}
```

真实样本必须列出全部已安装水草；上例为节省篇幅只展示一个数组元素。

## 9. 训练时派生的数据含义

JSONL 被读取后还会派生下列概念：

| 名称 | 来源 | 含义 |
|---|---|---|
| `positions` | 每株 `x/y` | 模型读取的逐株二维位置 |
| `plant_angles` | 每株 `angle` | 审计和物理查表信息；当前不直接进入网络 forward |
| `single_drag` | `physical.yaml` 按 angle 与 flow speed 查表 | 每株孤立基准阻力，单位 N |
| `global_features` | `flow_speed` | 整个样本共享的全局流速特征 |
| `raw_target_drag` | `measurements.FX_0` | 原始总阻力标签 |
| `target_drag` | 负值策略处理后的 FX_0 | 实际参与训练和主要指标的标签 |
| `plant_mask` | batch 动态补齐产生 | 区分真实植株与 padding，不是实验字段 |

不同样本水草数不同。批处理时会补齐到当前 batch 的最大水草数，补齐位置由 mask 排除，不代表真实空水草或零阻力水草。

## 10. 物理配置 `model/configs/physical.yaml`

该 YAML 文件不是训练样本，而是单株基准阻力查表。顶层字段：

| 字段 | 含义 |
|---|---|
| `version` | 配置 schema 版本，当前为 1 |
| `drag_unit` | 阻力单位，当前为 `N` |
| `states` | 角度状态字典 |

每个状态包含 `angles_deg` 和 `single_drag_by_flow_speed`。当前只允许已配置的角度和速度组合。新增实验角度或流速时，必须先补充物理表或重新定义缺失值策略，不能让程序静默外推单株基准值。

## 11. 运动轨迹 CSV

`Experiment/motion_profile.py` 生成根目录：

```text
output/V_0.10.csv
output/V_0.20.csv
output/V_0.30.csv
output/V_0.40.csv
```

表头为：

```text
t,x,y,z,b,c,vx,vy,vz,vb,vc
```

| 字段 | 物理意义 | 写出单位 |
|---|---|---|
| `t` | 轨迹时间 | s |
| `x,y,z,b,c` | 各控制轴位置 | mm |
| `vx,vy,vz,vb,vc` | 各控制轴速度 | mm/s |

当前运动主要沿 x 轴，其余轴用于保持控制器需要的完整格式。`output/renamed/` 中的数字文件是设备侧编号副本，`mapping.json` 记录原文件名与数字编号的对应关系。它们是控制输入，不应与模型的 `model/artifacts/` 混淆。

## 12. 训练预测 CSV

典型 `*_predictions.csv` 表头：

```text
source_index,sample_id,model_id,angle,flow_speed,raw_target_drag,
target_drag,predicted_drag,isolated_drag,target_C,predicted_C,fold
```

| 字段 | 含义 |
|---|---|
| `source_index` | 样本在训练所用 JSONL 中的零起始行位置，用于回溯 |
| `sample_id` | 原始样本标识 |
| `raw_target_drag` | 未做负值截断的 FX_0 |
| `target_drag` | 训练和评估实际使用的总阻力 |
| `predicted_drag` | 模型预测总阻力 |
| `isolated_drag` | 假设每株互不影响时，单株基准阻力的总和 |
| `target_C` | `target_drag / isolated_drag`，条件级真实相互作用系数 |
| `predicted_C` | `predicted_drag / isolated_drag`，条件级预测相互作用系数 |
| `fold` | 产生该预测的交叉验证折编号 |

这些文件是模型输出，不是新实验标签。尤其不能把 `predicted_drag` 合并回正式汇总 CSV 充当真实 `FX_0`。

## 13. 逐株 coefficient CSV

典型 `*_plant_coefficients.csv` 表头：

```text
source_index,sample_id,model_id,angle,flow_speed,plant_index,
x,y,plant_angle,single_drag,latent_coefficient,fold
```

`single_drag` 是物理配置查得的基准值，`latent_coefficient` 是网络内部为总阻力预测学习的潜在系数。两者相乘后对样本中的所有水草求和，形成 `predicted_drag`。

`latent_coefficient` 没有直接实验标签，不能单独作为真实测量发表或与传感器逐株力等同。

## 14. 数据新增与替换检查表

新增原始实验条件时：

1. 保持 `model_N ↔ input.csv 第 N 行` 映射。
2. 使用 `sensor_A_angB.csv` 命名，并确认 A 的速度映射。
3. 确保无表头、逗号分隔、六列顺序不变。
4. 记录采样率、单位、传感器和实验同步信息。
5. 先运行过滤，再运行汇总；不要手工拼 JSONL。
6. 对非正式新批次可暂用汇总脚本的 `--no-strict` 排查，正式接纳后应更新严格基线和测试。
7. 对生成的 CSV/JSONL 核对行数、流速分布、构型数和缺失条件。
8. 使用新产物目录训练，保留数据路径与配置快照。

直接替换 JSONL 时：

1. 保持 schema version 与精确字段集合。
2. 检查 `vegetation_layout`、`plants.grid_index` 和 `x/y` 一致。
3. 检查每个 `sample_id` 唯一。
4. 检查 `flow_speed` 可在 `physical.yaml` 中查到。
5. 明确该文件是完整基线、训练子集、外部评估集还是可视化副本。
6. 不要覆盖唯一副本；速度筛选脚本会原地替换目标文件。
